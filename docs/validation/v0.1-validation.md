# Signal Quality Validation — V0.1

Signal quality validation runs at **step 4.5** in the pipeline, after asset class validation and before idempotency. It applies to all BUY signals that reach this step.

A rejection at this step returns HTTP 422 and writes a `signal_quality_rejected` event to `webhook_events`. No `Signal` record is created.

---

## Validation Rules

Rules are evaluated in fail-fast order. The first failure short-circuits the rest.

| # | Rule | Condition | Reason Code |
|---|------|-----------|-------------|
| 1 | Price is positive | `price > 0` | `invalid_price` |
| 2 | Stop loss present and positive | `stop_loss != null AND stop_loss > 0` | `invalid_stop_loss` |
| 3 | Take profit present and positive | `take_profit != null AND take_profit > 0` | `invalid_take_profit` |
| 4 | Stop loss below entry | `stop_loss < price` | `stop_loss_above_entry` |
| 5 | Take profit above entry | `take_profit > price` | `take_profit_below_entry` |
| 6 | Risk/reward ratio sufficient | `(take_profit - price) / (price - stop_loss) >= MIN_RISK_REWARD` | `risk_reward_too_low` |
| 7 | Timeframe in allowlist | `timeframe in ALLOWED_TIMEFRAMES` (skipped if list is empty) | `unsupported_timeframe` |
| 8 | Signal not stale | `now - event_time <= MAX_SIGNAL_AGE_SECONDS` (skipped if 0) | `stale_signal` |

Rules 4 and 5 use strict inequality (equality is rejected) to prevent division by zero in the risk/reward calculation.

---

## Settings Reference

| Setting | Default | Description |
|---------|---------|-------------|
| `MIN_RISK_REWARD` | `1.5` | Minimum acceptable risk/reward ratio. Accepts Decimal. |
| `ALLOWED_TIMEFRAMES` | `5m,15m,1h` | Comma-separated list of accepted timeframes. Empty = allow all. |
| `MAX_SIGNAL_AGE_SECONDS` | `900` | Maximum age of `event_time` in seconds. `0` = disabled. |

Set via environment variables or `.env`:

```
MIN_RISK_REWARD=2.0
ALLOWED_TIMEFRAMES=5m,15m
MAX_SIGNAL_AGE_SECONDS=600
```

---

## Edge Cases

| Scenario | Behaviour |
|----------|-----------|
| `price` absent or non-numeric | Schema validation rejects it (`schema_invalid`) before quality gate |
| `price = 0` or `price < 0` | Quality gate catches it (`invalid_price`) |
| `stop_loss` or `take_profit` absent/null | Treated as invalid (`invalid_stop_loss` / `invalid_take_profit`) |
| `stop_loss == price` | `stop_loss_above_entry` (equality is rejected) |
| `take_profit == price` | `take_profit_below_entry` (equality is rejected) |
| `ALLOWED_TIMEFRAMES=[]` | Timeframe check is skipped entirely |
| `MAX_SIGNAL_AGE_SECONDS=0` | Staleness check is skipped entirely |
| SELL signals | Rejected at step 3 (side validation) — never reach quality gate |

## Example Payloads

**Accepted (HTTP 202)**

```json
{
  "secret": "...",
  "client_signal_id": "momentum:1.0:SPY:5m:2026-05-20T14:30:00Z:buy",
  "strategy": "momentum_pullback",
  "version": "1.0",
  "ticker": "SPY",
  "side": "buy",
  "price": "450.00",
  "stop_loss": "445.00",
  "take_profit": "458.00",
  "timeframe": "5m",
  "bar_time": "2026-05-20T14:30:00Z",
  "event_time": "2026-05-20T14:30:01Z"
}
```

Risk/reward: `(458 - 450) / (450 - 445) = 8 / 5 = 1.6 ≥ 1.5` ✓

**Rejected — risk_reward_too_low (HTTP 422)**

```json
{
  "price": "450.00",
  "stop_loss": "440.00",
  "take_profit": "464.00"
}
```

Risk/reward: `(464 - 450) / (450 - 440) = 14 / 10 = 1.4 < 1.5` ✗

**Rejected — stale_signal (HTTP 422)**

```json
{
  "event_time": "2026-05-20T12:00:00Z"
}
```

If current time is `2026-05-20T14:30:00Z`, age = 9000 seconds > 900 ✗

## Audit Trail

Every quality rejection writes one row to `webhook_events`:

| Column | Value |
|--------|-------|
| `event_type` | `signal_quality_rejected` |
| `reason_code` | one of the 8 reason codes above |
| `reason_detail` | human-readable detail string (e.g. `risk_reward=1.4000 min=1.5`) |
| `client_signal_id` | extracted from the signal |
| `masked_payload` | payload with `secret` redacted |
