# Signal Generator — V0.2b

The signal generator is a standalone Python CLI tool that replaces TradingView alerts for local development. It downloads OHLCV data, calculates EMA 21 and ATR 14, detects a simple EMA crossover, and either prints or POSTs a payload to `POST /webhook/signal`.

It does not connect to Alpaca, does not place orders, and does not modify the FastAPI server.

---

## Quickstart

```bash
# 1. Enable in .env
PYTHON_SIGNAL_GENERATOR_ENABLED=true
SIGNAL_GENERATOR_SECRET=your-webhook-secret

# 2. Dry-run (print payload, no HTTP call)
python -m src.signal_generator.cli --ticker SPY

# 3. Send to running server
python -m src.signal_generator.cli --ticker SPY --send
```

---

## Operating Modes

| Mode | Flag | Description |
|------|------|-------------|
| dry-run | _(default, no flags)_ | Prints payload JSON to stdout. No HTTP call. |
| send | `--send` | POSTs to `SIGNAL_GENERATOR_BACKEND_URL/webhook/signal`. |
| force | `--force` | Bypasses the crossover check. Sends/prints regardless of market condition. Useful for pipeline testing. |

Modes can be combined: `--send --force` sends even without a crossover.

---

## Settings Reference

| Setting | Type | Default | Description |
|---------|------|---------|-------------|
| `PYTHON_SIGNAL_GENERATOR_ENABLED` | bool | `false` | Hard gate. Must be `true` to run. |
| `SIGNAL_GENERATOR_BACKEND_URL` | str | `http://127.0.0.1:8000` | Base URL of the running server. |
| `SIGNAL_GENERATOR_SECRET` | str | _(required)_ | Must match the server's `WEBHOOK_SECRET`. |
| `SIGNAL_GENERATOR_TICKERS` | list | `SPY,QQQ,AAPL,MSFT,NVDA` | Comma-separated list. Runs once per ticker. |
| `SIGNAL_GENERATOR_TIMEFRAME` | str | `15m` | Bar interval. Supported: `1m`,`5m`,`15m`,`30m`,`1h`,`1d`. |
| `SIGNAL_GENERATOR_PERIOD` | str | `5d` | yfinance lookback window (e.g. `5d`, `60d`). |
| `EMA_LENGTH` | int | `21` | EMA span for crossover detection. |
| `ATR_LENGTH` | int | `14` | ATR rolling period. |
| `ATR_MULTIPLIER` | Decimal | `1.5` | `stop_loss = price - ATR × ATR_MULTIPLIER`. |
| `RISK_REWARD` | Decimal | `2.0` | `take_profit = price + risk × RISK_REWARD`. |

## Signal Logic

**Crossover condition (BUY):**
```
previous_close <= previous_ema  AND  current_close > current_ema
```

**Price levels:**
```
price      = current_close (last completed bar)
stop_loss  = price - ATR × ATR_MULTIPLIER
risk       = price - stop_loss
take_profit = price + risk × RISK_REWARD
```

At default settings (ATR_MULTIPLIER=1.5, RISK_REWARD=2.0):
- Risk/reward ratio = 2.0, which satisfies the server's default `MIN_RISK_REWARD=1.5`.

## `client_signal_id` Format

```
python_atr_generator:0.2b.0:{ticker}:{timeframe}:{bar_time}:buy
```

- `bar_time` is the UTC start time of the current closed bar in `%Y-%m-%dT%H:%M:%SZ` format.
- The same string is used in both the `bar_time` payload field and inside the ID.
- The ID is **deterministic**: the same bar always generates the same ID, providing idempotency through the server's duplicate check.

Example:
```
python_atr_generator:0.2b.0:SPY:15m:2026-05-20T14:30:00Z:buy
```

---

## Partial Bar Rule

yfinance may include a partially completed bar as the last row of the download. The generator always skips `df.iloc[-1]` and uses:

- `df.iloc[-2]` → **current closed bar** (price, EMA, ATR, bar_time)
- `df.iloc[-3]` → **previous closed bar** (for crossover comparison)

This rule is unconditional and not configurable.

## Server Response Handling

| HTTP Status | `reason_code` | Generator action |
|-------------|---------------|-----------------|
| 202 | — | Log `signal accepted: approved=True` |
| 200 | `risk_rejected` | Log `signal accepted: approved=False` |
| 409 | `duplicate_signal` | Log `signal already processed`, exit 0 |
| 422 | any quality code | Log rejection detail, exit 1 |
| 401 | `invalid_secret` | Log rejection detail, exit 1 |
| Other | — | Log status + detail, exit 1 |

A 409 is **not an error**. It means the same bar was already processed (e.g., generator ran twice within the same 15-minute window).

## Exit Codes

| Code | Meaning |
|------|---------|
| 0 | Success, no crossover, or duplicate (all normal) |
| 1 | Fetch error, network error, or server rejection |
