# V0.3b — Outcome Evaluator: Operator Guide

## Overview

The Outcome Evaluator is a standalone CLI tool that reads forward-tested signal records from `forward_test_runs`, downloads subsequent OHLCV bars via yfinance, evaluates whether each BUY signal reached its take-profit or stop-loss, and persists a complete audit trail of outcomes and PnL metrics in the `signal_outcomes` table.

It never calls Alpaca, never places orders, and never modifies `forward_test_runs`.

---

## Quickstart

1. Enable in `.env`:
   ```
   OUTCOME_EVALUATOR_ENABLED=true
   ```

2. Run once (dry-run to preview):
   ```bash
   python -m src.outcome_evaluator.cli --once --dry-run
   ```

3. Run and write to DB:
   ```bash
   python -m src.outcome_evaluator.cli --once
   ```

4. Evaluate a single signal by ID:
   ```bash
   python -m src.outcome_evaluator.cli --client-signal-id "python_atr_generator:0.2b.0:SPY:15m:2026-05-20T14:30:00Z:buy"
   ```

## CLI Flags Reference

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--once` | flag | — | No-op. Accepted for cron/launchd readability. |
| `--tickers` | str | `OUTCOME_EVALUATOR_TICKERS` | Comma-separated tickers. Overrides env var. |
| `--timeframe` | str | `OUTCOME_EVALUATOR_TIMEFRAME` | yfinance interval (e.g. `15m`, `1h`). |
| `--period` | str | `OUTCOME_EVALUATOR_PERIOD` | yfinance lookback window (e.g. `5d`, `30d`). |
| `--lookahead-bars` | int | `OUTCOME_LOOKAHEAD_BARS` | Max bars to evaluate per signal. |
| `--include-dry-run` | flag | `False` | Include signals sourced from `is_dry_run=true` forward-test rows. |
| `--client-signal-id` | str | `None` | Evaluate a single signal by ID, bypassing ticker filter. |
| `--dry-run` | flag | `False` | Evaluate and print results, but do not write to DB. |

## OutcomeStatus Reference

| Status | Definition | Terminal? | Exit code contribution |
|--------|-----------|-----------|----------------------|
| `take_profit_hit` | A post-entry bar's high >= take_profit | Yes — immutable | None (exit 0) |
| `stop_loss_hit` | A post-entry bar's low <= stop_loss | Yes — immutable | None (exit 0) |
| `ambiguous_same_bar` | Same bar hits both tp and sl | Yes — immutable | None (exit 0) |
| `timeout` | `OUTCOME_LOOKAHEAD_BARS` exhausted without hit | Yes — immutable | None (exit 0) |
| `pending` | Insufficient future bars available | No — re-evaluable | None (exit 0) |

Terminal outcomes (`take_profit_hit`, `stop_loss_hit`, `ambiguous_same_bar`, `timeout`) are never overwritten. `pending` rows are re-evaluated on every run until they resolve.

## `signal_outcomes` Schema

| Column | Type | Nullable | Description |
|--------|------|----------|-------------|
| `id` | String (UUID4) | No | Primary key |
| `client_signal_id` | String | No | Unique — one row per signal |
| `ticker` | String | No | Equity ticker |
| `timeframe` | String | No | Bar interval |
| `entry_price` | String (4dp) | No | Entry price from `forward_test_runs.price` |
| `stop_loss` | String (4dp) | No | Stop loss price |
| `take_profit` | String (4dp) | No | Take profit price |
| `bar_time` | DateTime (UTC) | No | UTC start of entry bar |
| `forward_test_run_status` | String | No | Status from source row (e.g. `signal_candidate`) |
| `is_dry_run_source` | Boolean | No | Whether source row was a dry run |
| `outcome` | String | No | `OutcomeStatus` value |
| `outcome_bar_time_utc` | DateTime (UTC) | Yes | Bar where outcome occurred; null for `pending` |
| `bars_to_outcome` | Integer | Yes | Bars elapsed until outcome |
| `pnl_r` | String (4dp) | Yes | PnL in R-multiples; null for ambiguous/timeout/pending |
| `pnl_pct` | String (6dp) | Yes | PnL as price ratio; null for ambiguous/timeout/pending |
| `max_favorable_excursion` | String (6dp) | Yes | Max `high - entry_price` over evaluated bars |
| `max_adverse_excursion` | String (6dp) | Yes | Min `low - entry_price` over evaluated bars |
| `evaluated_at_utc` | DateTime (UTC) | No | Updated on re-evaluation |
| `created_at_utc` | DateTime (UTC) | No | Immutable after insert |

---

## PnL Formulas

### `pnl_r` (R-multiples)

| Outcome | Formula |
|---------|---------|
| `take_profit_hit` | `risk_reward` from source row, or `(take_profit - entry_price) / (entry_price - stop_loss)` if absent |
| `stop_loss_hit` | `-1.0000` (always exactly -1R) |
| `ambiguous_same_bar` | `null` |
| `timeout` | `null` |
| `pending` | `null` |

### `pnl_pct` (price ratio)

| Outcome | Formula |
|---------|---------|
| `take_profit_hit` | `(take_profit - entry_price) / entry_price` |
| `stop_loss_hit` | `(stop_loss - entry_price) / entry_price` (negative) |
| `ambiguous_same_bar` | `null` |
| `timeout` | `null` |
| `pending` | `null` |

---

## MFE / MAE Semantics

- **MFE (Max Favorable Excursion)**: `max(high - entry_price)` over all evaluated bars up to and including the outcome bar. Positive for BUY when price rises.
- **MAE (Max Adverse Excursion)**: `min(low - entry_price)` over all evaluated bars up to and including the outcome bar. Negative for BUY when price falls.
- Both are stored as 6dp strings.
- For `pending` rows, partial excursion values from available bars are stored and updated on each re-evaluation.
- `null` if no post-entry bars are available.

---

## Idempotency Contract

- Terminal outcomes (`take_profit_hit`, `stop_loss_hit`, `ambiguous_same_bar`, `timeout`) are written once and never modified.
- `pending` rows are updated on every run until they resolve to a terminal outcome.
- If a `client_signal_id` already has a terminal outcome in `signal_outcomes`, the evaluator skips the entire evaluation and OHLCV fetch for that signal.
- The `client_signal_id` column has a `UNIQUE` constraint — concurrent runs cannot produce duplicate rows (one will get `IntegrityError` and roll back).

---

## `--period` and Data Availability

`--period` controls how much OHLCV history yfinance downloads (e.g. `5d` = last 5 trading days). The evaluator filters to bars strictly after each signal's `bar_time`.

**When to increase `--period`**:
- You have signals older than the default period.
- A signal remains `pending` across multiple runs (not enough future bars in the download window).

**Example: evaluate a 10-day-old signal**:
```bash
python -m src.outcome_evaluator.cli --period 15d --client-signal-id "..."
```

---

## `--client-signal-id` Mode

When `--client-signal-id` is provided:
- The ticker filter (`--tickers` and `OUTCOME_EVALUATOR_TICKERS`) is ignored.
- The evaluator queries `forward_test_runs` for that exact `client_signal_id`.
- If not found or not evaluable, prints `no_candidate_found: <id>` and exits 0.
- Useful for debugging individual signals or re-evaluating with a wider `--period`.

---

## Dry-run Mode

`--dry-run` evaluates and prints results but does not write any rows to `signal_outcomes`.

Sample output:
```
[python_atr_generator:0.2b.0:SPY:15m:...:buy] take_profit_hit | pnl_r=2.0000 pnl_pct=0.013333 bars=3
[python_atr_generator:0.2b.0:QQQ:15m:...:buy] pending | bars_available=5
```

No DB writes occur. Useful for previewing outcomes before committing them.

## Scheduling with cron

Run every 15 minutes during market hours:

```cron
*/15 9-16 * * 1-5 cd /path/to/alpacaview && python -m src.outcome_evaluator.cli --once >> /var/log/outcome_evaluator.log 2>&1
```
