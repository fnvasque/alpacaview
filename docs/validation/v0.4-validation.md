# V0.4 Validation — Streamlit Reporting Dashboard

## Overview

The V0.4 dashboard is a **read-only** Streamlit application that reads from the SQLite database produced by the V0, V0.2b, V0.3, and V0.3b pipelines. It has no connection to FastAPI, no access to Alpaca, and makes no writes.

**Data sources:**
- `forward_test_runs` — signal intake history from the forward-testing CLI (V0.3)
- `signal_outcomes` — outcome evaluation results from the outcome evaluator CLI (V0.3b)

## Quickstart

```bash
# Set the DB path (default: sqlite:///./alpacaview.db)
echo "DASHBOARD_DB_URL=sqlite:///./alpacaview.db" >> .env

# Run the dashboard
streamlit run dashboard/streamlit_app.py
```

The browser will open at `http://localhost:8501`.

## Pages Reference

| Page | Title | Data Source | Description |
|------|-------|-------------|-------------|
| 1 | Overview | `forward_test_runs` + `signal_outcomes` | 11 global KPI metrics + outcome distribution chart |
| 2 | Outcomes by Ticker | `signal_outcomes` | Per-ticker outcome breakdown, win rate comparison |
| 3 | Blocked Signals | `forward_test_runs` (risk_rejected) | Rejection breakdown by reason code and ticker |
| 4 | Daily Evolution | `forward_test_runs` + `signal_outcomes` | Trends over time: volume, TP/SL, win rate, avg R |
| 5 | Raw Data | Both tables | Filterable raw rows with CSV download, limit 1000 per tab |

## Sidebar Filters Reference

| Filter | Type | Applies To | Behavior |
|--------|------|------------|---------|
| Date range | Date input | Both tables | Filters `created_at_utc` (inclusive start, exclusive end+1) |
| Tickers | Multiselect | Both tables | Empty = all tickers |
| Outcomes | Multiselect | `signal_outcomes` only | Empty = all outcomes |
| Include dry-run runs | Checkbox | Both tables | Default OFF; when ON includes rows where `is_dry_run=true` / `is_dry_run_source=true` |

**Note**: Ticker and date filters apply independently to each data source. The date filter on `forward_test_runs` controls `total_signals`; the same filter on `signal_outcomes` controls all outcome-based metrics.

## Metric Definitions

| Metric | Formula | Data Source |
|--------|---------|-------------|
| `total_signals` | `COUNT(DISTINCT client_signal_id)` WHERE `status IN EVALUABLE_STATUSES` | `forward_test_runs` |
| `evaluated_signals` | `COUNT(*)` WHERE `outcome IN TERMINAL_OUTCOMES` | `signal_outcomes` |
| `pending_signals` | `COUNT(*)` WHERE `outcome = 'pending'` | `signal_outcomes` |
| `take_profit_hits` | `COUNT(*)` WHERE `outcome = 'take_profit_hit'` | `signal_outcomes` |
| `stop_loss_hits` | `COUNT(*)` WHERE `outcome = 'stop_loss_hit'` | `signal_outcomes` |
| `timeouts` | `COUNT(*)` WHERE `outcome = 'timeout'` | `signal_outcomes` |
| `ambiguous_signals` | `COUNT(*)` WHERE `outcome = 'ambiguous_same_bar'` | `signal_outcomes` |
| `win_rate` | `take_profit_hits / (take_profit_hits + stop_loss_hits)` | Computed in Python |
| `avg_r` | `mean(pnl_r)` for non-null values | `signal_outcomes` |
| `total_r` | `sum(pnl_r)` for non-null values | `signal_outcomes` |
| `avg_pnl_pct` | `mean(pnl_pct)` for non-null values | `signal_outcomes` |

**EVALUABLE_STATUSES**: `signal_candidate`, `risk_approved`, `risk_rejected`, `duplicate_signal`

**TERMINAL_OUTCOMES**: `take_profit_hit`, `stop_loss_hit`, `ambiguous_same_bar`, `timeout`

## Win Rate Formula

```
win_rate = take_profit_hits / (take_profit_hits + stop_loss_hits)
```

**Denominator whitelist**: Only `take_profit_hit` and `stop_loss_hit` are included. The following are explicitly excluded from the denominator:
- `pending` — outcome not yet resolved
- `timeout` — no directional result
- `ambiguous_same_bar` — both TP and SL hit on the same bar; no clean outcome
- Any future outcome values (`no_data`, `error`, etc.)

`win_rate` is `None` (displayed as `—`) when `take_profit_hits + stop_loss_hits == 0`.

## Blocked Signals Scope

The Blocked Signals page shows `forward_test_runs` rows where `status = 'risk_rejected'`. This represents signals that were received, validated, and then rejected by the Risk Engine before any order was placed.

**V0.4 limitation**: Only the forward-testing pipeline is shown. Raw webhook events (`webhook_events` table) and detailed risk decision logs (`risk_decisions` table) are available for future pages.

## Data Source Separation

`total_signals` and outcome metrics use **different tables with different `created_at_utc` timestamps**:

- A signal generated on 2026-05-20 creates a `forward_test_runs` row with `created_at_utc = 2026-05-20`.
- The same signal may be evaluated on 2026-05-22, creating a `signal_outcomes` row with `created_at_utc = 2026-05-22`.

When the date filter is set to `2026-05-20`, `total_signals` will include this signal but `evaluated_signals` will not. This is intentional and expected.

## Dry-Run Behavior

When **"Include dry-run runs"** is unchecked (default):
- `forward_test_runs` rows where `is_dry_run = true` are excluded from all metrics
- `signal_outcomes` rows where `is_dry_run_source = true` are excluded from all metrics

When checked:
- All rows are included regardless of dry-run status

This allows comparing dry-run performance against live-mode performance independently.

## Performance Notes

- The **Raw Data** page limits results to the most recent **1000 rows per tab** to avoid browser performance issues.
- All other pages aggregate at the database level (GROUP BY queries) and are not subject to the 1000-row limit.
- The SQLAlchemy engine is cached via `@st.cache_resource` — it is created once per Streamlit process and reused across all reruns and pages.
- Individual sessions are created per page render and closed immediately after use.

## Configuration

| Variable | Default | Description |
|----------|---------|-------------|
| `DASHBOARD_DB_URL` | `sqlite:///./alpacaview.db` | Path to the SQLite database (or PostgreSQL URL for production) |

Add to `.env`:
```
DASHBOARD_DB_URL=sqlite:///./alpacaview.db
```

```
DASHBOARD_DB_URL=postgresql://user:password@host:5432/dbname
```
